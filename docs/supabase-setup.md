# Supabase 接入与上线

本仓库支持单管理员云端工作区。Supabase 负责 Auth 和数据库，网页由 GitHub Pages 托管；排班仍在浏览器运行。没有配置环境变量时，原本地系统照常工作。

## 当前使用方式

[公网管理入口](https://krc6666.github.io/autoschedule-new/)已上线。使用在 Supabase 中创建并绑定的管理员邮箱、密码登录。首次导入配置后点击“保存到云端”；以后登录会读取已上传的配置，修改后再点保存，不需要每次导入导出。班表继续通过原有 Excel、HTML 或 PNG 导出发送，公开发布是可选操作。

本次已由管理员确认“本机保存到云端 → 公网入口重新登录 → 看到同一配置”。页面和43个构建文件的公网字节已核对；手机宽度检查通过，真实手机运营商网络未实测，owner已明确不将公开班表及其流量测试作为本次目标。

当前 Pages 从 `gh-pages` 分支根目录发布静态生产包。更新网页需要验证、重新构建并更新发布分支；仅修改源码或仓库变量不会自动替换这份生产包。现有云端资料保存在 Supabase，不需要随网页更新重新导入。实际发布版本及一次性历史验收放行授权见[部署结果](acceptance/evidence/2026-11-15-supabase-deployment-complete.json)和[授权记录](acceptance/evidence/2026-11-15-supabase-release-authorization.json)。

## 目前能做什么

- 管理员用邮箱、密码登录，读取两组人员、规则、共用航班、当前班表与归档历史。
- 编辑仍走原 Store 和排班安全链。日常本机保存不代表已上传；点击顶部“保存到云端”后，另一台电脑才能读取。
- 两台电脑打开同一旧版本时，后保存的旧版本被数据库拒绝，不覆盖新版本。
- 管理员点“发布当前组班表”，生成该组、该日期的查看链接。同一组、同一天再次发布沿用链接，刷新后看最新发布。
- 查看者不登录，只能读取该链接对应的发布快照，没有配置、完整历史库、人员编号、内部诊断或修改权限。
- 公开快照只含航班号、岗位、人员姓名、开始/结束时间、岗位备注和安排状态。班表中的姓名会向拿到链接的人显示；内部人工备注和系统诊断不公开。当前公开页不展示轮值汇总、统计页或配置页。
- 草稿修改、云端保存和公开发布是三件事。未保存修改、过期班表、计算中和历史编辑未提交时不允许发布。发布失败保留上次发布。

## 注册后按顺序接入

### 1. 建免费项目

到 <https://supabase.com/> 注册，创建 Free 项目，等待项目可用。区域按实际使用网络选择，先用手机流量测试访问；本仓库没有验证你所在地运营商到任何区域的速度。

数据库密码只由你保管，不发聊天、不写进仓库或前端环境变量。Free 在连续 7 天低活动时可能暂停，需到控制台恢复；免费档不是永不休眠的服务器。官方免费条件见 [协议核查](research/supabase-preparation-contract.md)。

### 2. 安装数据库脚本

在项目 SQL Editor 执行 [数据库迁移](../supabase/migrations/202611150001_cloud_workspace.sql) 全文一次。不要只执行其中一部分。脚本在事务中建立私有工作区、唯一管理员记录、发布快照和 RPC；客户端没有直接表读写权。

也可以用 Supabase CLI 的 migration 工作流部署此文件。`supabase/config.toml` 已准备，但本次没有安装或运行官方容器栈；Windows 本地全栈需要 Docker 兼容引擎。不要在生产项目运行 `db reset`。

### 3. 创建唯一管理员

在 Authentication 的用户管理中创建一个邮箱/密码用户，设为已确认邮箱。后台按钮名称可能随控制台版本变化，以“创建已确认的邮箱密码用户”为准。

关闭允许新用户注册；网页也不提供注册入口。关闭注册不等于数据库授权：即使另一个用户成功登录，管理 RPC 也会拒绝它。

在 SQL Editor 打开 [设置管理员脚本](../supabase/set-admin.sql)，仅在控制台里把 `REPLACE_WITH_ADMIN_EMAIL` 换成刚创建的邮箱后执行。脚本只允许一个管理员，重复执行同一邮箱不变；已有不同管理员时拒绝替换。

不需要把 service-role/secret key 提供给网页。所有管理 RPC 都使用登录用户 JWT，并在数据库中核对唯一管理员。

### 4. 本地填写两项公开配置

把 `.env.example` 复制成 `.env.local`，在你本机填写：

```dotenv
VITE_SUPABASE_URL=https://你的项目.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=你的publishable公开密钥
```

项目 URL 和 publishable key 从项目 Connect/API Keys 获取。也支持旧版 anon key。不要填数据库密码、`sb_secret_...` 或 `service_role` key；构建和运行入口会拒绝这些配置。

`.env.local` 已被 Git 忽略。`VITE_*` 会进入公开网页产物，不能用于任何秘密。修改后重启 `npm.cmd run dev`，进入管理员登录页。

### 5. 首次迁移并核对

先在原本地系统导出备份。配置 Excel 只包含当前组及共用资料；如果两组都有资料，分别保留 A、B 两份，不能把单份导出误当整套双组备份。

云端为空且使用原网站同一浏览器存储时，点“首次从本机迁移”。它将完整本机模型带入编辑区，保留原本地存储，不立即上传。检查两组人数、岗位、规则、日期、历史与共用航班，再点“保存到云端”。

换域名或换浏览器时，原本地存储不跟随。可以按组使用原有 Excel 导入，或在已有云端工作区用“下载恢复副本”导出完整两组 JSON，再到新设备“导入恢复副本”。恢复副本先替换编辑区，仍需核对并保存；文件中的旧版本号不会替代数据库的当前版本。

未提交的排班准备表单和缩放/选日等视图选择按原合同留在当前浏览器，并按项目、账号隔离，不是云端正式资料。

### 6. 配置 GitHub Pages 构建

在仓库 Settings → Secrets and variables → Actions → Variables 添加两项 repository variables：

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

两项都用上面的公开配置，不填写任何私密 key。现有 Pages 构建已读取这两项；未设置两项仍构建原本地版，缺一则构建失败。变量在构建时生效，修改变量后需要重新构建。

仓库现有验收/发布门禁仍保留。先补齐真实项目和页面验收材料，再按已授权发布流程部署；创建账号或填变量本身不会在本次准备中自动上线。

## 真实验收

按启用的功能检查下面各项，自动测试不能代替实际入口。公开分享相关条目仅在需要该功能时验收；已执行和未执行的范围以任务验收记录为准：

1. 未登录打开管理网址，只看到登录入口；错误密码不能进入；另一个普通 Auth 用户也不能读取配置或修改。
2. 管理员在 A 设备保存，B 设备登录后核对两组和共用资料；打开旧版本的 A 设备再保存，必须收到冲突，B 数据保持。
3. 保存后发布，复制查看链接，用退出登录的浏览器和手机流量打开；只看到该组、该日期发布行，没有配置、内部备注或编辑入口。
4. 编辑但不发布，查看链接仍是旧版；再次成功发布，原链接刷新后更新。模拟发布失败，原发布仍可读。
5. 核对原有排班、手调、归档、历史编辑取消、停止计算、Excel 导入导出和准备表单记忆。云端操作不得带走历史编辑草稿或计算中方案。
6. 断网保存失败时，本页仍有修改；刷新后的本机恢复副本保留。新设备不能把未上传修改当成云端成功。
7. 用实际历史规模核对容量、延迟与公开页手机布局，记录项目版本和验收证据。

## 失败与恢复

- **旧版本冲突**：先下载恢复副本备份，再退出并重新登录读取最新云端。需要恢复旧内容时，处理旧副本提示后导入 JSON，人工核对差异再保存；系统不自动合并两台电脑的修改。
- **本机旧副本与云端不同**：编辑暂停，先下载副本，再明确选择放弃本机旧副本使用云端。这个动作不删除云端数据。
- **本机存储不可写**：修改可能只在当前页面，立即下载恢复副本或按原入口导出 Excel。上传成功与本机恢复副本成功分别提示。
- **云端读取失败或坏数据**：不使用初始示例数据冒充云端，也不自动开放本地编辑入口。检查网络、项目暂停状态、迁移和管理员记录。
- **需要退回原本地版**：移除两项云端构建配置并重新构建，不执行删库。云端恢复副本、Excel 和原本地存储保留；新云数据不会自动覆盖到原本地存储。
- **备份**：定期保留完整 JSON 恢复副本和按组配置 Excel。Free 项目不能下载平台数据库备份，管理员可另用官方 CLI `db dump` 备份整个数据库；Auth 用户及账号恢复需遵循 Supabase 官方迁移流程，不能把应用 JSON 当完整平台备份。

## 验证证据与边界

离线阶段用 PGlite 的本地 PostgreSQL 引擎实际执行迁移和角色授权测试，涵盖 RLS、RPC、旧版本拒绝、发布白名单及失败原子回退；Auth 角色声明由测试模拟。另有官方 Supabase SDK 的传输测试及 DOM/控制器测试。

接入后已检查真实 GoTrue/PostgREST、匿名管理接口拒绝、44行真实发布快照及独立浏览器展示、公网登录入口和生产文件哈希；管理员确认真实登录、保存和公网重新登录读取配置。真实双设备旧版本冲突、断网及另一普通账号尝试仍只具备本地/模拟回归证据，不宣称已做现场验证。公开注册设置按owner要求保留；历史待验收记录没有删除，本次上线使用已明确授权的一次性放行，后续发布门禁不变。
