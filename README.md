# 自动排班

### 把航班、岗位资质、人员状态和历史负荷整理成可执行的机场保障班表。

云端版新增“历史版本”：每次覆盖保存前自动备份完整A/B两组及共用资料，只保留最近20个旧版本。列表显示原保存时间和原上传账号；共用账号只能看到同一个账号。恢复前需确认，成功时替换整个工作区并先备份当前云端资料，取消或失败保留本机修改；旧设备版本冲突仍拒绝覆盖。已发布班表需另行发布。启用前上传账号未知，之前已覆盖的数据无法补回。此功能需先安装[增量SQL](supabase/migrations/202611170001_workspace_versions.sql)及配套前端；本地代码完成不代表云端已启用，部署和现场状态见任务验收记录。

规则页默认全部折叠，搜索会展开匹配项。任何规则修改都先保留为草稿，统一点击页面上方“保存规则”后生效，再重新排班；云端版还需点击顶部“保存到云端”上传。督导补位的“完成本条编辑”也只是加入草稿，直接点整页“保存规则”可一起保存当前补位编辑。未保存时切页、切组、进入操作记录或退出会提醒；取消离开继续保留修改，确定则放弃。关闭/刷新由浏览器原生确认，未保存草稿请勿直接离开。开合和搜索不算修改，改回原值无需保存。

规则页可分别开启“提前下班均衡”“下午无航班均衡”，两项目标差距默认1，默认均开启。保存规则后重新排班，系统参考本月此前完整归档班表，尽量把机会分给次数少的人；请及时归档，草稿不作历史。资格、锁定、值班、半休和人员保护优先，受限时可能超过目标；关闭仍保留统计，不改写旧历史。开关与差距随配置Excel迁移，导入后可继续使用。

“规则 → 核心保护与公平参数”的“工时与疲劳均衡”也包含近期点数补充均衡：按“历史统计天数”（默认最近7天）的已保存实际岗位疲劳，加本班点数，尽量把较重任务交给近期较轻的人。原当天疲劳差目标、资格、覆盖、恢复、重点岗位公平和航班数继续优先；当天目标内可以一轻一重，不强求每班相等。近期调节也适用于宽松或少于4个航班的班次，后续休息均衡/舒适性换人共同复核。排班后的“负荷均衡”显示实际窗口与近期累计差；无法兼顾时保留合法安排。原开关和统计天数随配置Excel、保存恢复迁移，没有独立账本；请归档完整班表，缺失历史不猜补。历史窗口跨月滚动，不等于统计页的自然月累计。

生成排班、重新排班或归档并排后天失败时，提示先用一句话说明原因。需要了解细节时，点击“查看原因和解决办法”，查看已知问题和处理步骤；原因暂时不明确也会说明。失败不会采用新班表。需要开发人员检查时，可在详情中导出本次诊断记录。成功生成后，黄色提醒列出空岗及简短原因；其他说明请看“排班反馈”。

## 日常使用

云端登录页请求浏览器不要自动填入密码，提交后立即清空密码框；浏览器可能忽略这项设置。Chrome若已保存排班网站密码，请在地址栏打开`chrome://password-manager/passwords`，找到该网站记录并删除，以后出现保存提示时选“永不”。网页不能代替你删除浏览器密码；仅退出系统不会删除浏览器已保存的密码。

云端工作台顶部“操作记录”打开独立页面，可查看账号、时间和每次成功保存后的修改，展开用中文文字只列实际变化及必要的航班/岗位定位，每条修改都显示这次云端保存的日期和时分，支持查看更早记录；返回工作台可继续原编辑。人员、资质、规则、班表及导入/恢复的实际变化统一留痕，查看页面和同值重复保存不记。保存前改过又改回不留过程；共用管理员账号不能区分具体同事。记录从数据库新迁移启用后开始，配置Excel和恢复副本不能清除它，也不包含它的备份；需随数据库备份迁移。当前源码已提供，远端数据库启用和网页发布须分别完成。

云端版登录后，顶部显示“保存到云端”和保存状态；发布、恢复副本下载/导入、退出登录在右侧“…”菜单。点击保存立即显示进度，成功显示具体时间，5秒后简化为“已保存”，悬停可看日期和时间；失败显示原因分类和“点击重试”，同时弹窗提醒并保留修改。再次编辑会显示“有修改未上传”。未保存或正在保存时关闭/刷新页面会请求浏览器离开确认，退出登录会先提醒保存；保存成功且没有新修改则不再提醒。浏览器关闭确认的文案和展示由浏览器控制；原工作台的配置和班表Excel操作保留。

“规则 → 航司搭配偏好”可维护尽量避免全天只做某组航司的组合，默认FD、AK。每条填写航司代码，可新增、修改、启停或删除；保存后重新排班生效。系统有安全替代才换人，不增加个人航班数、不拉长普通员工的工作跨度；当天只有组内航班或无法安全换人时允许原搭配。设置按组保存在本机，并随配置Excel带走。

换设备时，在A电脑刷新当前版本、确认设置并导出配置，再到B电脑导入。预览识别到整份配置后默认选中“换设备完整恢复配置”，按文件恢复当前组人员、岗位资质、规则、半休、轮值、次数修正，以及共用航班模板、每周计划和当天航班；文件外旧航班移除，不让本机旧设置混进来。当天航班与模板不同的时间分别保留，完整岗位名称、0疲劳点和手动岗位资质都能带过去。另一组已有人员、规则及当天班表保持，历史仍按原方式合并，行政支援模式按本机选择。文件没有记录上午/晚上四项统计时间、休假类别或半休选择时，预览会列明统一初始设置：上午06:00—12:00、晚上18:00—次日06:00、无自建类别、无半休人员；只补缺少的项目，已有值仍按文件恢复，不沿用本机旧值。这些初始值不代表源电脑未导出的设置；要带上源电脑的实际选择，请用新版导出配置，新版会一并保存。缺少其他必需内容、存在错误或仍有人员引用缺失的自建类别时，预览会说明并阻止完整恢复，原数据保留。确实只想导入部分配置时，可取消完整恢复，继续使用普通导入或单独替换模板。

本季航班默认按当前组“岗位配置”确定，每个航班可标为“本季启用”或“暂不使用”。暂不使用的航班保留岗位性质、人员资质、疲劳点及相关规则，恢复时继续使用；航班计划和排班选择只提供本季启用的航班。共用模板库可保留以前用过、以后可能恢复的航班；未使用的备用模板即使没有时间，也能随完整配置导入并原样保留，启用前再补齐。真正删除的模板不会因为导出、切组、刷新或完整恢复而重新补回；岗位配置与过去历史独立保留。

在B组的“航班核对”点击“B组本季航班按A组更新”，先查看新增/重新启用、暂不使用和时段变化，再确认。本季航班固定以A组为准，不再反向要求用B核对A；B更新一致且岗位配齐后，黄色换季提醒自动消失。B组已有岗位的名称、性质、资质、疲劳和备注不被A组覆盖；新航班只进入本季名单，需要另配B组岗位和资质，配好前不能直接算成已完成。停用航班从B当天列表移出，但整套岗位配置留着；A组当天选择、两组人员、历史和次数记录不复制或删除。匹配的B当天航班按共用模板更新时间，之后需重新排班。也可沿原核对入口逐项明确新增或旧号换号；“旧航班已停用，删除本组”是另一个明确删除岗位和相关规则的操作，不能与“暂不使用，保留岗位”混为一谈。新增的本季启用状态随当前组配置导出；旧文件没记录该状态时，完整恢复按岗位配置确定本季并说明，普通局部导入则保留本机选择。导出仍为当前组及共用资料，不是两组人员和规则的整套备份。

“统计 → 人员岗位疲劳”显示右上角工作日期的当日岗位疲劳，以及所选月份从月初累计到该月最新班表的疲劳点数；包含原有值班额外疲劳，同一天当前班表与归档只算一次，不加连续工作惩罚。月份默认现实日期所在月，可以切换查看旧月份；新月没有班表时从0开始，旧月数据保留。该表从排班页移到统计页，只调整统计查看，不改变排班使用的疲劳与恢复规则。

“规则 → 核心保护与公平参数 → 统计时段设置”可分别维护上午、下午、晚上的起止时间，默认收起；下午默认12:00—18:00，晚上可跨午夜。当前“下午无航班”次数使用下午时段：当天该时段有航班，且某位当天参加过排班的常规人员没有任何岗位与该时段重叠，才计1次；只要有一段重叠就算上过班，包含引导、督导补位。整个下午没有航班，所有人都不计次。仅在12:00结束、18:00开始不算重叠。下午时段同时联动值班避排，但值班避排只看航班开始时间；上午和晚上的设置暂不新增对应计次，也不改变半休、值班上午或夜班资格规则。设置按组保存并随配置Excel带走；历史根据已保存事实重算，缺少的旧出勤信息不从当前模板猜补。

“统计 → 月度轻松班次统计”改为人员纵列、已选航班横列，默认选可用MF/CX航班；展开“调整统计航班”可勾选、全选或清空，按A/B组保存并随配置Excel迁移。航班列仍统计符合原提前下班条件的最后航班，每人每天最多一次。另有“下午空”（下午窗口没有任务，窗口后还有航班）和“下午休”（当天有排班，但没有开始时间晚于12:00的航班，12:00本身也不算晚于），两项互斥。点击数字展开日期，0次显示暂无日期；可独立切月。清空航班仍保留两项下午列；取消勾选不删除历史。新两项只用于查看，原“下午无航班”摘要和自动排班均衡口径保持。

配置页的“航班计划模板”放在“排班约束”下面，单独占一整行，方便查看较长内容并操作每行右侧的删除按钮；新增、编辑和删除方法不变。

需要增加“飞行假”等休假名称时，展开“配置 → 人员信息”，点击“管理休假类别”小按钮，在原处展开后输入名称并点击“新增休假类别”，再到人员的“状态”下拉框选择该名称；再次点击管理按钮可收起。生成、重新排班和归档后天的状态确认窗口也可选择；所有自建类别与原“休假”遵守相同限制。类别按 A/B 组分别保存，并随导出配置 Excel 带到其他设备。类别可改名和停用；停用不改变已有人员状态，仍有人使用时不能删除。没有使用的类别可确认删除。

设置督导补位时，在“规则 → 督导补位关系”点击“新增补位关系”或“编辑”，从航班模板中只选择一次航班，再选该航班的“督导岗位”和“补位岗位”，设置自动/人工补位后点击页面上方“保存规则”。岗位配置只显示关联，点击“管理督导补位”可进入同一入口。换季时在航班模板修改航班号，A/B 两组关系与当天航班会同步更新，不需另改规则页；保存规则后仍需重新排班。督导只在同一航班内补位；旧跨航班关系保留为待处理，不再执行。旧配置若显示“待确认”，请编辑核对后先“完成本条编辑”，再“保存规则”；本次未选对应航班会提示“本次不适用”，不能仅凭启用开关判断实际补位。关系随配置 Excel 保存，原普通人员优先及安全检查继续生效。

自动排班先补齐能安全安排的岗位，再尽量保留“跨航班重点人员优先”。存在空岗时，会尝试普通换人；仍补不齐时，也会按已启用的同航班督导补位关系，让督导兼任配置柜台，再把腾出的合格人员经连环换人补到重叠航班。人员互斥、资质、时间、工时、半休和锁定继续严格检查；没有完整安全方案时保持原安排，不把空缺挪到其他岗位。岗位已齐时不会为此强制督导兼任。

所有机动督导都优先独立安排。H05等已配置补位柜台仍与其他普通柜台一起正常排班，不预先留给督导，也不指定某人必须接某柜台。合格督导正在柜台上时，系统会尝试让其他普通人员接柜台、释放督导；排班收尾再检查现有兼任，先对各航班尝试直接接替，再尝试完整换人。能够安全拆开且不新增空岗时，保留已轮换的督导本人，柜台恢复普通人员、实际工时和疲劳；确实缺人或没有完整安全方案时保留兼任。人工指定和锁定岗位不自动拆改。

删除模板航班不会自动丢弃岗位资质：岗位页会把仍有规则但没有模板的航班标记为“无模板航班”。确认“清理岗位规则”后，才会清理 A、B 两组该航班的岗位规则并使受影响班表失效；当前航班和历史仍保留。

修改航班模板的开始或结束时间后，匹配的 A、B 组当天航班时段会同步更新并保留预定人数。受影响班表会清空，需要重新排班；系统不会拿旧人员安排套用到新时段。某组当天没有匹配航班时，该组当前班表不变。

要按真实班表重新手工录入，可点击排班工具栏的红色叉叉“清空全部人员”，确认后当前班表所有岗位的人员都会清空，航班、岗位、时段及备注保留，可以直接重新填写。取消不会修改班表，清空不影响另一组班表或历史记录。

历史班表也支持：在“历史”中点击“编辑该日排班”，再点同一红叉，即可清空这份草稿的全部岗位人员。重新录入后点“保存并更新历史”才会写回该日期；点“取消编辑”则放弃草稿，恢复原历史和进入编辑前的当前班表。

编辑历史时，原航班号和已保存的岗位时间继续保留，不会套成现在的模板时间；换人、保存后再打开也保留。旧记录没有有效时间时才使用模板时间，无法匹配的航班或岗位会提示并阻止覆盖保存。

生成排班、重新排班、归档并排后天遇到局部设置或约束问题时，只把无法合法安排的岗位留空，其他合法岗位照常采用。后续调整出错会先撤回那次调整。半休没有合适岗位时允许当天无岗；值班计划选中了休假或病假人员时，保留计划并提醒换人，不给该人员安排自动岗位。资格、时间冲突和工时等安全检查仍严格执行。

生成成功后，右下角黄色提醒列出空岗的航班号和岗位，每条后面点击“原因”可展开该岗位空着的说明，默认收起；没有记录时会明确说明，长内容在框内滚动。生成排班、重新排班和归档并排后天都采用此方式，不重复其他软约束等反馈。班表人员格不显示原因控件，方便直接输入和拖动补人；“排班反馈”和排班 Excel 的“系统说明”仍保留。程序崩溃、数据损坏或计算没有产生可靠结果时，仍保留原班表。

1. 先在页面顶部选择 A 组或 B 组。两组使用同一套航班模板和每周航班计划，但人员、岗位分类/资质与排班规则分别保存；同一岗位在两组可以有不同性质和配置。岗位只在当前组“岗位配置”维护：增删、改名和排序后，下面航班模板自动显示当前组名单，切换组就显示另一组岗位，不需要再手填一遍。没有配置的航班显示“尚未配置岗位”。模板航班号、时间和备注仍两组共用，导入模板不会替任何组补岗位；导出配置中的岗位名单也按当前组配置生成。导入岗位配置时，规则中有但模板中没有的航班会自动补到两组共用模板，已有模板内容保留；时间从文件或现有当天航班读取，没有来源时留空。文件含“每周航班计划”时，确认配置导入就会按文件选择更新两组共用计划，不需要重新勾选星期和航班；预览会逐日显示最终导入结果，并列出模板中不存在、因此会跳过的航班。计划表缺少星期、重复或无效星期、表头无法识别时会指出错误行或缺失星期并保留现有计划；只有表头仍表示明确清空七天计划。文件不含计划表时也保留现有计划。导入预览默认只更新当前组规则；勾选“整体替换共用航班模板”后，才会用文件整体替换两组共用模板。模板航班号支持使用 `CX937(早)`、`CX937(晚)` 这样的后缀区分不同时间版本；修改模板航班号会同步更新两组的岗位规则和当前航班引用。岗位规则分组内可选择目标航班，一键复制当前组全部岗位及资质人员；目标已有岗位时会先确认覆盖。
2. 在“航班”中确认当天航班、时间、运力和岗位；也可以使用在线查询生成增删建议。在线查询不可用时不影响本地排班。
3. 选择工作日期并生成排班，在真实任务进度完成后查看班表、右侧提前下班与下午无航班名单、人员负荷和规则反馈。
   班表下方的“人员当日航班”默认显示当前日期，可切换查询其他已归档工作日；列出全部常规人员，包含病假、休假和没有航班的人，行政支援不列。姓名后用括号注明当前具体假别，例如“张三（飞行假）”；没有航班显示 0 和“未安排”，病休人员不会因此收到漏排提醒。航班号去重且不列岗位；查询旧班表保留实际航班，假别仍表示目前人员设置。没有完整归档或只有末班重点记录时，页面会明确提示而不会补猜全天航班。
   上方固定三行“全天无航班人员”“上午无航班人员”“中午以后无航班人员（半休）”，没人也显示“无”。自动检查正常常规人员，全天无人只列第一行；其他人员只按记录开始时间判断：不晚于12:00算上午，晚于12:00（包含晚班）算午后，不看结束时间。比如11:50开始、13:00结束且没有其他航班，仍列“中午以后无航班”；12:01开始则算午后有航班。人工改派和查询完整历史后自动更新；没有完整记录显示“无法判断”。这里只核对名单，不自动设置半休，也不改变右侧和统计页的月度计次口径。
   第四行“重叠航班人手检查”会扫描当前班表中多个航班同时保障、且有缺岗或实际机动督导补位的时段。展开可看航班/岗位、该时段空闲人员和逐岗位“直接检查通过”名单；不通过的原因也可展开。空闲一小段不代表能接完整岗位，检查会核对资质、全岗位冲突、工时、衔接、半休等；分队长标明需人工补差。同一空闲人不能同时补多个岗位，结果供人工核对，不自动换人；补好后自动更新。没有触发项仍保留结论。历史及历史编辑缺少空岗/补位证据时明确无法完整检查。此处重叠看保障起止，首尾相接不算，与前三行只看开始时间的分类不同。
   规则页“同一工作班航班数均衡”会在岗位覆盖、值班、KE166、资质、状态、时间冲突、最小衔接和工时等安全规则锁定后，使参与比较人员承担的不同航班数最大值与最小值相差不超过 1。同一航班多个岗位只计一次；行政支援、病假、休假以及当天没有安全候选航班的人员不参与比较。无法在安全规则下完成均衡时，只保留带结构化均衡回退证据的空岗；后置覆盖、恢复、轮岗和人工调整不会为均衡制造空岗。
   当天需要安排半休时，在生成或重新排班前打开“半休人员”并勾选一个或多个正常常规人员。下午半休人员只能承担 12 点前开始的岗位，上午半休人员只能承担 12 点后开始的岗位；这是硬限制，恢复、轮岗、覆盖和岗位压缩都不能突破。半休人员尽量安排符合时段的合法岗位；没有合适岗位时允许当天无岗并说明原因，其他合法岗位照常生成。系统先遵守值班、资质、冲突、衔接和工时等安全规则，再在允许时段内优化半休人员的岗位；非半休人员即使命中疲劳恢复、截止保护或严格恢复目标，只要缺少其他安全人选，也会继续正常上班填补半休造成的后续空缺。严格恢复只在这类实际补位时让步，普通换人仍不能突破。半休选择按当前组、工作日期保存；刷新或切回该日期会恢复，其他日期不串用。导出配置和排班Excel会保留选择，旧文件缺少标记时不推测。
   点击“重新排班”会先打开当前日期的航班确认窗口。窗口显示当前组岗位配置中的本季航班，默认勾选其中当天已有航班并带入当前预定人数，其他本季航班人数默认 0；备用模板和已退出本季的当天航班不再提供排班选择。可以临时增减航班、修改人数后再确认，人数达到岗位配置的“启用旅客人数”时对应柜台才会自动安排。取消、点击“停止，不采用”或计算失败时，原航班、人数和班表保持不变；明确点击“停止并采用”时，只有完整安全方案可与本次航班选择一起提交。本次选择不会改写航班模板、每周计划或历史。
   值班人员优先上最早能合法排全的上午航班（默认06:00至12:00前，按航班保障开始时间）；跨航班优先、普通轮岗和疲劳偏好让路。同一航班可换柜台；没资格或会造成缺岗时尝试下一班，没有合法上午岗位则保留其他安排并提醒。后续普通调整不能把早班改晚，只有净补原空岗且不产生新空缺时允许让步。原晚撤、KE166专项和人工调整权限继续保留。规则页“规则如何执行 → 值班岗位锁定与下午避排”可查看完整说明，也可搜索“下午避排”。航班开始时间落在规则页的下午起止范围内（含起点、不含终点），优先安排其他合格人员，确实缺人才用值班兜底；不为了凑航班数量补下午任务。下午结束后开始的航班仍可用于公平补班：比普通参与人员最高数少超过1班时，尽量补到只差1班，再考虑减负，不额外增加上午任务。例如下午结束17:30，17:55开始的航班可补班；结束改18:00，该航班便优先避排。初排和后续换人均联动这些设置；资质、半休、时间和工时等限制照常遵守，不能补足时保留合法班表，并在值班反馈中显示时段、最终航班数量和原因。不会为了凑数清空别人的岗位。
4. 按需要拖拽换人、交换岗位、填写临时岗位或调整当日轮值。人工调整可以突破资质、时间重叠、衔接和每日工时限制，但会在单元格、反馈和归档中持续标明原因；病假、休假、夜班能力不足、人员不存在、行政支援模式关闭和机动督导兼任范围仍不能突破。
   自动排班最后会检查普通员工“上午做完后一直等到末班、中间没有其他任务”的情况，值班人员豁免；尽量通过安全换人缩短全天跨度，个人航班数保持，不靠加航班填空，也不把同样的早晚割裂转给别人。目标员工为缩短全天跨度可让出当天“下午无航班”计次，实际统计照常重算，其他人员休息机会和原公平要求继续保护。上午联动规则页原时段设置，末班按当天实际最晚结束航班判断，不按航班号写特例。没有安全改善方案时保留合法班表，并在反馈中列出仍存在的时段与空挡；规则页搜索“早晚任务集中”可查看说明。本次针对这种明确形态，不保证消除所有形式的长空挡。
   规则页可添加多条“同航班人员互斥”，每条勾选至少两名人员，也可勾选三名或更多；同一航班最多安排其中一人，例如勾选甲乙丙，则任意两人都不能同班。每条规则可单独启停，停用仍保留人员选择；航班留空表示适用于全部航班，选择具体航班则只限制该航班。配置修改只标记当前班表需重排，不自动换人；自动排班和后续校验遵守互斥，人工显式突破保留原红色警告。旧两人配置会保留为两人组，多人选择随配置导出、导入和备份恢复迁移。
   班表中的岗位名称或人员格旁的加人图标可以点击查看该岗位当前合格且空闲的常规人员；列表不显示有时间冲突或不合格的人员，点击姓名即可直接安排。点击列表外其他位置会自动收起，再点原入口也可收起，点另一岗位入口直接切换。人员输入框本身仍保留原有姓名补全列表，用于手工输入。
5. 在“统计”中核对月度值班、CX航前、备勤和岗位承担次数，在“历史”中复核已归档班表。完整历史日期展开后点击“编辑该日排班”，系统精确匹配现有航班和岗位，恢复历史人员并保留已保存时段；可在排班页继续换人、交换或清空岗位，点击“保存并更新历史”后覆盖该日期历史，同日当前班表一起更新，其他日期当前班表保留。编辑期间原历史保持不变，点击“取消编辑”放弃草稿并恢复进入编辑前的当前班表；仅末班重点历史记录不能编辑。
6. 导出 Excel、离线 HTML 或 PNG；确认当天结果后可以仅归档，或点击“归档并排后天”，确认目标星期预设的航班后再归档和生成。统计页的末班重点岗位表可切换自然月份，并按“人员 × 已勾选航班”同时显示各航班次数；点击某个航班数字展开当前配置或所选月份记录涉及的类别，申报/送资料二合一岗位只显示“送资料”，同航班另有独立申报岗时仍显示“申报”。当前月份可一键清零，也可用“导出次数 / 导入次数”专用 Excel 在设备间完整迁移最终次数；专用文件只包含各航班实际适用类别，旧文件若给二合一岗位提供“申报”行会整表拒绝并提示重新导出。导入前会预览并校验月份、人员、航班、类别、整数和完整性，确认后覆盖该月文件范围，不重复累加。清零和修正都会进入下一次自动排班均衡，人员列表不会因手工改数重新排序。配置导出仍保留原始“末班重点次数修正”账本。历史页还可以导入旧版按日期分工作表的手工排班 Excel，导入时手动选择工作日期，系统只展示并写入当前末班重点规则范围内且实际晚于末班界线的重点岗位记录；下午航班和其他岗位不计入末班重点次数。此类“只导入末班重点”的记录保留岗位业务备注和配置疲劳点，用于末班重点轮换、恢复保护和已知重点疲劳，但不会被当作完整班表参与“下午无航班”“提前下班”、完整班次滚动工时或完整连续工作日统计。

统计页的普通重点岗位区块也可独立切换自然月份，默认跟随当前工作日；该区块按所选月份显示普通重点次数，现有手工修正按钮写入所选月份，不影响末班重点岗位的月份选择。

统计表选择岗位筛选后，普通重点表对应整列用浅蓝底和边线突出；末班重点表突出所选类别的汇总、最高/最低摘要和展开明细。切换岗位时标记跟随，选择“全部”恢复，手机布局也保留对应单元格标记；次数计算、原筛选及加减操作不变。

岗位备注修改后，末班重点次数会按当前岗位配置重新归类，包括已保存的历史。例如 TR121/H04 改为“申报/送资料”，原先记为“申报”的该岗记录也计入“送资料”1次，不再计申报；历史原备注仍保留。统计页、自动末班轮换和次数 Excel 使用这一口径。普通重点仍计在“TR / H04”，不会因备注改变而丢失。

现有次数表按实际岗位计数，不因岗位配置中的“分流”“机动督导”等分类漏计。例如同一人承担一次 TR121 督导，在已选末班航班且晚于末班界线时，原“督导”项就记 1 次；普通重点仍按已配置的航司和完整岗位名称统计。旧版手工班表的仅末班导入也采用此口径。不增加统计列，自动排班规则保持原样。引导仍不计重点岗位次数；兼任引导不新增负荷历史、不重复计算工时与疲劳，独立引导则保存实际负荷；不追溯清理已有历史。

统计页的月度轮值明细可单独切换值班与备勤月份，并沿用当前工作日的上一休一奇偶组；每个工作班日期仍可直接调整值班和次日备勤人选，CX 航前视图与全局工作日期保持不变。

月度提前下班统计按原配置节点判断最后一班；当天任一航班计划截载晚于 23:00 时整日不计提前下班，分流提前撤岗不改变航班计划截载。旧历史缺少原航班截载快照时，按已保存的结束时间统计。

先在“航班 → 每周航班计划”中为星期一至星期日分别勾选已有航班模板。“归档并排后天”会根据目标日期所属星期默认勾选对应预设，并提供“恢复星期预设”“全选”“清空”；弹窗里的临时增减和每个航班手动填写的预定人数只影响本次生成，不会改写每周计划。预定人数达到岗位配置的启用旅客人数时，该岗位才会自动安排。取消、点击“停止，不采用”、失败或没有完整安全方案时，原日期、航班、历史和班表均保持不变；点击“停止并采用”会采用后天最近一份完整安全班表，同时归档本班并切换到后天日期。这个流程只使用本机模板，不要求网络或在线查询。

不参加备勤的人员，可以在“配置 → 人员信息”中关闭“备勤资质”。关闭后，自动轮值、手工选择和值班备勤 Excel 导入都不会再把该人员安排为备勤；若合格人员不足，备勤席位会留空并提示。

点击“生成排班”或“归档并排后天”先选航班、填写预定人数，并确认当前组人员的正常、病假、休假状态，再点击确认开始排班。三个排班入口都默认沿用当前已保存的人员状态，下一班不自动把休假或病假人员改为正常，只需调整有变化的人。弹窗调整在排班成功前只是草稿；成功后人员状态与配置页同步，刷新或导入该次导出的配置后仍保留。取消、失败或点击“停止，不采用”均保留原航班、人员状态和班表；点击“停止并采用”通过安全检查后，人员状态与班表一起保存。“重新排班”保持原有航班选择流程。

所有打开“确认航班、状态与轮值”的按钮共用准备记忆。同组同一天调整的航班勾选、人数、人员状态、行政支援开关和值班备勤，关闭或取消后再开、刷新网页、关闭浏览器再开都会保留；归档后天按后天日期保存，不会串到本班或另一组。没有该日记忆时才读取原默认。窗口中修改只是草稿，取消、计算失败或停止不采用不改正式班表，草稿仍可继续调整；确认排班并通过安全检查后才提交正式结果。修改其他人员状态也保留仍有效的轮值选择。已删除的航班/人员和失效选择不会恢复；恢复初始数据会清空准备记忆。这份未提交记忆只保存在当前浏览器，不随Excel转移；浏览器无法保存时会提示刷新可能丢失。

三个排班准备窗口最上方都有“是否启用行政支援模式”，无该日准备记忆时沿用当前模式。先选模式，再核对航班、人数、人员状态和轮值，点击确认后只计算一次；成功后同步班表工具栏的模式开关。窗口里切换模式只是草稿，取消或失败不会改变原模式和班表，不需要先排班再切模式重算。三个入口的“停止并采用”都一起采用最近一份完整安全班表和所选模式；“停止，不采用”保留原模式和班表。

每次点击“生成排班”或“重新排班”，系统只计算当前选中的日期，不会提前计算未来两三个班。当天需要自动安排的岗位和所有合格人员会放在一起考虑；当前月份没有末班重点岗位人工次数账本时最多计算 150 秒，录入或清零该月次数后最多计算 5 分钟，求出完整结果会立即结束，不会固定等待满 5 分钟。超过允许时间或计算失败时不会采用半成品，原班表会继续保留；确实缺少合格人员的岗位可以留空，并显示原因。计算期间可以点“停止，不采用”立即结束并保留原班表；生成排班、重新排班、归档并排后天及其他即时计算流程中，后台准备好一份完整且通过安全检查的方案后，“停止并采用”会启用；点击后立即结束后续计算，显示并保存最近一份安全方案。尚无安全方案时不能采用，原班表保留。跨工作日恢复目标可选择“优先避开”或“严格限制”；严格限制通常禁止恢复人员承担目标岗位，只有填补半休造成的后续空缺时才受控让步。没有半休补位例外且无人能合法承担目标岗位时，该岗位留空并说明原因，其他合法岗位照常生成。

整次排班从开始计算起最多等待10分钟；正常算完会立即返回，不会固定等满。到10分钟会自动结束：已经准备好可用班表时，采用最近一份检查通过的结果，保留合法安排和有原因的空岗；还没有可用的新班表时，保留原班表。生成、重新排班、归档并排后天，以及模式切换或人员状态触发的重算都使用这项保护；归档后天采用时同时保存本班历史并切换日期。原有人员资质、休假、冲突、工时和最终安全检查继续执行，不采用未经检查的半成品。150秒或5分钟指整体岗位计算的预算，10分钟是包含后续调整的整次等待上限。旧环境不支持后台线程时，页面被同步计算占用可能延迟自动结束，恢复执行后不会用迟到结果覆盖已结束的班表。

排班失败时右下角的红色错误提示会一直保留，直到点击提示右侧的关闭按钮；带有原因和处理办法的提醒也会一直保留，方便展开查看；其他普通消息仍按原定时间消失。

次班截止时间是上一班末班重点人员在下一班最晚允许继续工作的界线，不要求恰好在该时刻下班。存在多个完整安全方案时，系统按截止更早、上一班结束更晚、最终工作结束更早的顺序，优先把更早下班机会给受保护人员。

人员配置中勾选“分队长”后，该人员仍可正常承担有资质的岗位，但系统不要求他每天必须出现在班表中，也不会为了凑齐“人人有工时”而专门安排岗位。存在安全替代人员时，连续承担 `KE166` 独立督导的分队长可以整班休息；只有分队长是唯一合格人员或更高优先级规则确实需要时才继续安排。

规则页的“分队长补差岗位保护”按岗位分类列出当前全部“航班号 / 岗位名”，可整类批量保护或允许，也可展开修改单个岗位。普通重点岗位默认保护，排班员明确放开后才可进入补差换人链；值班人员当前岗位、`KE166`、人工、行政支援、已补差落地岗位、督导兼任关联格和特殊布局关联格固定保护，不能从该页关闭。设置随浏览器状态和配置 Excel 保存。

排班页“分队长补差”可以选择非 `KE166` 的自动常规空岗和自动机动督导空岗，例如 TW616 的“督导/引导”。有资质的分队长可以直接接岗，也可以通过换人腾出合格人员；先查看整体预览，再一次确认。已有岗位的移动保护继续有效，无安全方案时显示原因并保留原班表，不会启用并行督导；不用把机动督导分类改成常规。

所有明确配置为“机动督导”的顶部岗位都会在普通柜台排定后依次尝试独立安排、允许范围内兼任和安全重排。有不占柜台的合格人员时优先独立；缺员兼任必须同航班、两格同人、工时只计一次，两个岗位的疲劳分别累计，并继续遵守规则页的兼任范围。全部方式都无法安排时，顶部保留空缺和普通告警，不拆已经形成的普通岗位方案。

指定补位柜台留空时，如果普通人员能安全承担，会尝试补上普通人员，督导保持原安排；最后检查撤掉不合法兼任后也会再次尝试，避免有人可用却一直空着。半休、资格、时间、工时等限制照常检查，已有合法人员或合法兼任的柜台不因此改人。

`KE166` 继续保留额外专项：无法安排时使用专属标红与人工复核文案；若同一常规人员在“跨航班重点人员优先”中被选入 `KE166` 行，并且 `KE166` 行排在该人员对应的重叠航班行上方，督导和柜台要优先保留两名不同常规人员；必要时让排在后面的 `CX937` 等航班岗位空缺，行政支援人员不算这名额外真人。确实没有第二名安全常规人员时，仍保留合法兼任兜底。`KE166` 督导组连续轮岗和跨航班专项不推广到其他航班。

自动引导优先复用同一航班行政支援岗位上已经填写的常规人员；没有这类人员时，再按整条岗位顺序从最下面已经上岗的正常常规人员开始复用。行政支援岗位上的常规人员可以且优先成为引导，行政支援人员本人不能成为引导。多个引导岗位依次复用不同人员，不重复计算工时、疲劳或历史。

需要专人引导时，直接在引导人员格选择或填写正常常规人员姓名；该人没有兼任本航班其他岗位时，系统记为独立引导，按实际时段计工时、按引导岗位设置计疲劳点数。例如先清空CX931不需要的末端柜台，再把该人填入柜台引导即可。后续换其他柜台人员不会改掉独立安排；保存、Excel及归档保留实际负荷。若选本航班已上岗人员则仍为兼任。独立安排后又给同人安排重叠岗位会按原人工规则提醒；需改回兼任时先清空引导再填写。重新排班仍会按自动规则重新安排。空岗红色、半休、KE166及人工越权说明沿原规则。

开启行政支援模式后，系统先保证常规体系岗位，再把仍满足资质、状态、夜班、时间冲突、衔接和工时上限的常规人员自动排入行政支援岗位；该规则不限定航班号或航班时间，常规人员已有其他不冲突岗位时也会继续安排。所有常规人员都不能合法承担时，岗位才留空供手工拖入行政支援人员。行政支援人员始终不参加自动排班；常规人员承担支援岗位正常计算工时、疲劳和历史，行政支援人员手工承担仍不计算。

规则页的“普通岗位最小衔接间隔”默认是 90 分钟。同一个人做完一个航班后，到下一个航班开始必须至少留够这段时间；刚好 90 分钟可以，89 分钟不可以。唯一跨航班例外是有效分流：来源岗位已设为“分流”、来源航班在 12:00 及以后开始，按原结束时间计算会与下一航班重叠或衔接不足，配置的提前撤岗能够消除冲突，并且不使用分流就会造成岗位缺口时，可以提前撤岗后接续。同等岗位完整度下优先减少分流转派。自动排班、补缺和轮岗仍严格执行人员状态、资质、夜班能力、时间冲突、衔接和每日工时上限；人工调整可以在这些可控限制上直接落位并报警，系统会保留具体原因，不会把人工越权带回自动排班。病休、夜班能力不足、人员不存在、行政支援模式关闭和机动督导兼任范围仍会阻止人工调整。

规则页还可以按顺序添加“跨工作日资质预留”。例如下一工作班某航班的控制岗位至少要留 1 名合格人员，系统会尽量避免今天把所有控制资质人员都排到过晚的岗位，但被保留的人今天仍可做较早、较轻的工作。它不会提前生成下一班，也不会为了预留故意空掉今天本来能填的岗位；两边实在无法兼顾时，今天岗位照常填满，并明确提示下一班还差几名可用人员。

规则页顶部搜索框可以搜索规则名称、说明、参数名称和当前配置内容。例如输入航班号、岗位关键词或 `90`，对应的规则卡会自动展开，无关规则会暂时隐藏；清空搜索后恢复全部规则。

规则页会检查航班号、岗位和人员是否还能对上配置。黄色短提示表示需要修正；“本次不适用”“已关闭”是中性说明。需要帮助时点“查看原因与处理方法”，详情会写明原因、应去哪个页面、修改哪个字段，默认不展开。修改模板航班号会同步两组对应的当前航班，保留当天人数、时段、岗位与备注，并清除受影响班表。以前已经留下的旧名称，需要在“配置 → 航班计划模板”下展开“检查当前航班名称”，为旧航班选择正确模板并确认修正，再生成排班；独立添加的航班可继续保留。若某组同时已有新旧名称，会拒绝修改并提示检查重复航班，不自动合并。已保存但失去对应岗位的末班范围仍会显示，可单独取消后保存。提示不是自动排班保证，人员资格、缺员、时段与安全条件仍按原规则检查。

规则页可设置“末班结束界线”，默认是 `23:00`，并勾选哪些航班参加末班重点岗位轮换。系统先守住分类差值，再避开上一工作班已经承担过任意末班重点岗位的人，然后依次比较本月四类合计、最近 8 个归档工作班合计，最后才分别平衡督导、一号、申报和送资料。同一个岗位的名称和备注合起来同时包含“申报”和“送资料”时只按送资料 1 次处理；分开的申报岗和送资料岗仍各算 1 次。旧账本中二合一岗位的申报修正不迁移、不再参与统计或排班。督导和一号的正常差值为 1，申报和送资料允许差值 2；范围内不报警、不强制追平，督导资质人员也可以因承担督导而少做申报和送资料。

督导、一号、申报、控制和送资料都按航班与岗位滚动轮换：所有合格人员轮完当前次数后，才开始下一轮。一般同岗轮换也把申报/送资料二合一岗位统一归为送资料，和末班统计使用同一口径。重点岗位次数优先于恢复、疲劳、普通岗位衔接和上一班轻重；但不会突破资质、人员状态、夜班、时间冲突、每日工时、值班或 `KE166` 锁定、岗位完整性和严格岗位衔接。

`TR121 / H02` 按“一号”计算，自动排班时每名合格人员每个自然月最多承担 2 次；全部合格人员都达到 2 次后，该岗位自动留空。这个上限只限制自动排班，排班员仍可人工拖拽超过 2 次。值班人员若安排到首选晚撤岗位会使一号次数差超过 1，系统会继续尝试下一个晚撤目标。

统计页的“普通重点岗位”按人员汇总：每个人只显示一行，每个“航司 / 规范岗位”占一列，顶部可选择“全部”或具体岗位。有当前资质或已有该项基础、实际安排、修正的常规人员都会显示，不因今日资质变化隐藏历史事实。点击次数展开“实际、修正”和加减按钮，并按末班重点表的样式列出该月实际承担日期（如11-02、11-06），仅显示日期。手工数值修正不补猜日期；最终次数为实际与修正之和且最低0。

人工换人可沿用现有受控越权规则，突破资质后仍可归档或“保存并更新历史”，保留实际人员和提醒；自动排班继续严格按资质安排。首次换人前的人员保留为次数基础，换人差额自动进入修正：甲换乙后，甲基础1、修正−1、最终0，乙基础0、修正+1、最终1。重复保存不会累加，取消历史编辑不改变原历史；清空岗位会扣回原人的次数。各项最终次数最低0，0时减号禁用，之后加1直接到1。修正差额可为负数。

在历史记录中修改当前班表同一天并点击“保存并更新历史”，排班页会同步显示刚保存的人员和备注，刷新后仍保持一致，无需为了同步再排一次。编辑其他日期不会覆盖当前班表，取消编辑仍恢复原表。已有规则失效提示会保留，需要按新规则重新排班；云端版仍需明确点击“保存到云端”，公开查看页仍需另行发布。

打开工作台或切换A/B组后，会自动选中该组最新班表的日期；没有班表才显示今天。手动改日期后，排班页显示那一天的内容：当前表可以直接调整，已保存历史按原人员和时段显示，并提供“编辑该日排班”；没有结果会明确提示，不借用其他日期班表。历史查看不会改写正在编辑的另一日，调整或导出历史请先点击“编辑该日排班”。已保存历史不会显示另一份过期当前表的警告；当前表本身的规则失效保护仍保留。

普通重点与末班重点均复用原来的次数表，不另设“突破资质”列或“未记录”文字。展开后的“实际”表示人工调整前的次数基础；在历史里人工换人（包括突破资质）并保存后，差额自动合入“修正”，与原有手点加减的修正一起计算，重复保存不重复加次数。不按今天的资质倒推旧记录的来源；导出配置和排班结果仍保留人工调整证据。历史航班或岗位名称不匹配仍禁止覆盖保存，需要先自行校正配置；本次不增加别名或模糊匹配。

统计页提供统一的“末班重点岗位统计”，默认汇总规则页已勾选航班的月度次数。主表固定人员顺序并显示跨航班四类合计，每个已勾选航班各占一列；点击航班数字展开该航班当前配置及所选月份记录实际涉及的类别、次数和加减按钮。次数根据记录的岗位原备注及当前对应岗位配置识别：过去 H05 做送资料、现在改成 H04 做送资料，两处实际承担都计入，不因清空旧岗位备注或人员没有该岗位资质漏计。督导、一号、申报同样适用；人工填写的说明和资质警告不用于识别职责，二合一岗位仍只计“送资料”。取消勾选只会让该航班暂时退出后续规则和当前统计，不会删除历史，重新勾选后会立即恢复。

班表生成后，可以在排班工具栏点击“对比上一班”，直接在当前页面上方展开当前排班日期之前最近一个已归档工作日的只读班表。当前班表继续保留在下方；没有更早归档时按钮显示“暂无上一班记录”。对照内容使用现有历史归档数据，不会修改班表或重新计算排班。

空岗的具体原因从黄色提醒每条后的“原因”展开，班表人员格仍用于输入和拖动；“排班反馈”的异常项可展开“查看具体原因”。说明保留实际挡住安排的规则、航班岗位和时段，例如“严格跨工作日恢复3人；跨航班优先1人”，展开后逐人说明。人工调整提示先说明是否已保留，再列突破的具体限制。没有记录就明确“原因未记录”，计算到时间上限明确“尚未找到完整方案”；当前直接安排不通过，不代表多人换岗一定无解。“排班结果”Excel 中同样保留“系统说明”，打印保障表不增加这段详情。

岗位旁出现琥珀色提醒时，点击图标即可打开“调整原因分析”。选择想交换的人员后，页面会先模拟两人岗位交换，列出能改善的情况、人工调整后需要留意的取舍和仍然不能调整的原因；可执行的人工越权不再二次确认，提交前仍会按最新班表做双向检查。

排班计算期间可以继续查看页面和缩放班表，也可以使用两种停止操作；再次计算、切换行政支援、修改数据、导入或归档会提示等待当前任务完成，防止两个操作同时改动班表。当前任务无论成功、失败或停止都会释放后台计算资源，之后可以直接重试。

## 页面入口

| 页面 | 用途                                                         |
| ---- | ------------------------------------------------------------ |
| 总览 | 查看当前日期、航班、人员和排班状态                           |
| 配置 | 维护人员、航班模板、每周计划、岗位和通用参数，导入或导出配置 |
| 航班 | 管理当天航班并进行线上计划对账                               |
| 排班 | 生成、复核、人工调整和导出当天班表                           |
| 规则 | 用中文查看、启停和调整允许配置的排班规则                     |
| 统计 | 管理月度轮值并核对人员与岗位统计                             |
| 历史 | 查看、导入、删除和清空已归档排班                             |

班表根据当前航班和岗位自动生成。航班增加到 5、6、7、8 个或更多时会继续扩展，超过可读宽度后仅班表区域横向滚动；当日轮值在桌面端固定显示于班表右侧，窄屏时自动移到班表上方。

排班页左侧人员名单与下方“人员当日航班”均显示连续序号，按各自显示顺序编号；下方保留全部常规人员的 0 航班行，全天未安排提醒只检查正常上班人员，可用于核对漏排。

“导出结果”Excel 的“保障明细”顶部显示航班班表，右侧仅两列姓名、没有序号列，列出当前组常规人员及具体休假名称，半休姓名格只填绿色、不加半休文字；CX航前、值班、备勤和提前下班汇总移至表格下方。列宽、换行及行高按内容设置，长备注完整保留；采用紧凑间距，并按整表尺寸保存50%—100%的默认缩放，尽量打开即看全，特别大的班表仍可滚动查看。半休选择随配置及排班文件的“半休选择”表保存。

业务数据默认保存在当前浏览器本地；“导出配置”Excel 包含当前组的人员、岗位规则、排班设置、轮值及跨日期历史，并附 A/B 共用的航班模板和每周计划。换设备后导入该文件时，规则写入当前选中的组；文件含每周计划表时，确认导入就会同步 A/B 共用计划。整份替换共用航班模板则在预览中单独勾选。过去记录即使不符合新设备上的当前人员资质也会保留并计入对应人员的轮次、工时和疲劳统计。旧版本地数据迁移时，原来唯一的规则配置会成为 A、B 两组各自的初始副本；v9及更早数据首次升级时还会为两组补齐模板清单里缺少的岗位行。配置和历史 Excel 只在当前设备中解析；未配置云端时没有账号或远端数据写入，配置Supabase后的保存与发布见接入指南。

配置或班表发生修改后，如果直接关闭浏览器标签页或窗口，浏览器会先提醒可能有未导出的内容。本提醒不会因为关闭动作自动导出文件；选择留下页面后，请手动导出配置。现有浏览器本地数据保存机制保持不变。

详细规则、数据边界、实现说明和验收标准统一以 [spec.md](./spec.md) 为准，README 不重复维护第二套说明。

## 本地开发

已上线的[云端管理入口](https://krc6666.github.io/autoschedule-new/)使用唯一管理员账号登录。导入原配置并点击“保存到云端”后，下次登录直接读取，不需要反复导入；以后修改仍需再次保存，班表可以继续沿原方式导出发送。云端保存、退出提醒与部署见 [Supabase 接入指南](docs/supabase-setup.md)。未配置云端环境变量时继续使用原本地版。

安装依赖并启动开发服务：

```powershell
npm.cmd ci
python dev.py
```

检查生产构建：

```powershell
python dev.py --preview
```

完整验证：

```powershell
npm.cmd run verify
```

行为或发布机制修改的任务验收与发布材料检查见 [任务验收记录](docs/acceptance/README.md)。GitHub Pages 上传前还会检查当前版本证据，缺材料的任务会阻止发布。

### 普通重点岗位轮换

在规则中把“航司／规范岗位名”加入普通重点名单并保存，重新排班后，名单内自动常规、分流、机动督导都按同一套次数与连续轮换机制处理。比如KE160和KE166的“督导”共用KE／督导次数，换航班号不会清零；其他航司单独计算。督导有关联补位柜台时整组换人，只有安全且具备完整资质的替代才会采用。人工指定、值班锁定、引导复用和行政支援仍沿原规则。

重点岗位名称框不可编辑，并显示“重点岗位名称固定”；配置命令尝试改名也会提示并保留原配置；导入后如提示普通重点没有匹配岗位，请核对航司和完整岗位名称。同航司模板换号和时间联动保持，历史记录不改写。没有完整安全替代时保留原安排，并按原连续和频率提醒规则解释原因。
